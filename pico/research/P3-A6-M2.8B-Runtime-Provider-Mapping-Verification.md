## Следующий источник доказательств

Не повторять `/proc/<pid>/maps` и не обходить отказ повышением привилегий. До новой device-facing задачи имеет смысл только офлайн проверить, существует ли на целевой Android 10/PICO конфигурации уже доступный unprivileged system diagnostic, который связывает PID с **полным mapped path и device/inode** без запуска камеры и изменения логирования. Например, агрегированный memory summary может показать имя библиотеки, но без device/inode способен дать максимум `PARTIAL`, не PASS по принятому критерию. Если такого точного read-only интерфейса нет, безопасного источника для полного runtime mapping доказательства в текущем scope не установлено; потребуется отдельное решение владельца о допустимом доступе, без автоматического root/SELinux обхода.

Даже точная mapping PASS установила бы только то, что установленный provider file отображён в QuickCamera процессе во время snapshot. Она не докажет вызов callback, получение SOF/BOOT_TS, timestamp units/clock domain, frame/request identity, физический exposure start или пригодность для Lighthouse.
